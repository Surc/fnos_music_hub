# 首次用户引擎配置与平台能力说明

## 配置与登录的区别

酷我公共搜索与当前允许的酷我下载不需要酷我账号；QQ 公共歌曲搜索也不要求 QQ 登录。Hub 仍验证飞牛音乐身份，用于隔离本地收藏、任务、凭据和下载文件。网易公开歌单不需要网易账号；QQ/网易私人歌单与推荐需要分别启用并由本人显式关联。

preview.3 首次安装保留 `users={}`，`qq_accounts_enabled=false`、`netease_enabled=false`。因此即使飞牛音乐登录成功，静态用户授权表仍未分配 Hot；`/api/me` 的 search/download 为空。此前安装验收只签收启动、停启和公开 HTTP，没有签收真实登录/下载，不能视为业务部署完成。

前台把“此用户尚未配置引擎”“可选账号模块未启用”“功能尚未实现”统称为“待接入”，并在已启用网易时仍使用未开放文案。修复后分别说明上述状态，酷我不显示绑定按钮，并明确公共模式无需平台账号；网易入口移除写死的“待接入”。下载准入和身份校验不变。

## 本次实际配置

用户本人完成登录并提供“我的”页显示的 GUID，明确授权读取、本机备份并修改 `hub.json`。仅给该 GUID 增加独立 loopback Hot:18787、专用令牌变量与不重叠的本应用下载目录；启用包内已有 QQ/网易模块。保留原 instance_id、state、反代/内网地址与管理员列表。未读取密码、`secrets.json` 或 `vault.key`，未替用户登录平台。

原配置备份在本机忽略目录和 NAS 同配置目录的 `hub.original.json`；上传后恢复 UID960 和 POSIX0600，回读与候选完全一致。Hub 停启成功；原生 status/health 包含已配置 Hot 的健康、禁止降级与真实下载目录核对。完整账号/搜索/下载链路仍须单独记录，不能用健康回读签收。

trim-cli 的 `file download-url` 输出会脱敏 uri，无法直接下载。本次经用户授权后使用 skill 文档中的受 Bearer 认证的 `/ogh/ac/h/multiple-download` 读取指定配置；现有 OAuth 会话只在内存中复用，不输出令牌或临时链接，不读取其他应用配置。

## 新包与验证

平台文案修复使用新版本 preview.4；实际构建提交、产物摘要、升级和测试结果随后另记，不把旧 preview.3 FPK 重标为修复后产物。本次不发布正式 Release。真实 QQ/网易账号、双用户 ACL、完整音乐下载与资源验收继续独立记录。

## 构建时检出的启停竞态

首个preview.4候选 `d95400a` 的包内256项通过，但普通Linux真实生命周期在“子进程退出后重新启动”检出registry删除竞态：exists检查后supervisor删除processes.json，status抛FileNotFoundError。该失败候选未安装/分发。改为直接读取、仅对文件已删除返回stopped，保留其他错误；新增确定性删除竞态回归，原生相关54项与Ruff通过。修复后必须按新提交重新组包。
