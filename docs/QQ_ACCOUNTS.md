# QQ 账号与只读目录开发链路

更新：2026-10-22（Asia/Makassar）。本轮已实现协议适配与前台，尚未用真实 QQ 账号或 NAS 签收。推荐结果是否随本人偏好变化，必须和来源客户端对照；当前响应明确为 `personalization=unverified`。

## 启用与使用

基础模式默认 `qq_accounts_enabled=false`，继续提供已有 QQ/酷我搜索及酷我下载。QQ 目录使用可选 QQMusicApi **库**，不增加第二个常驻服务或 Node/Docker。开发机安装 `python -m pip install -r requirements-qq.lock`；FPK 后续应预构建并打包依赖，不能要求 NAS 安装 Git、编译器或构建 SDK。

启用前备份 Hub 数据库与 vault.key；数据库会从 schema 1 自动增加账号/登录尝试两张表并升为 2，旧程序不能直接读取 schema 2。按 [原生运行](RUNNING.md) 以同一系统用户启动各自专用 Hot。设置 `qq_accounts_enabled=true`，重新启动 Hub；缺少可选 SDK 时启动会明确报错，不悄悄退回共享账号。

页面操作：

1. 用本人的飞牛音乐账号登录，在“我的 / 平台账号”选择“扫码登录 QQ”。二维码由本用户独立 Hot 创建，经授权的同源图片接口显示。
2. 用 QQ 音乐扫码确认，Hub 显示待关联 QQ 号。核对后点击“确认关联此 QQ 账号”；只读 SDK 检查平台登录有效后才保存关联。已有专用 Hot 登录也可选择“关联已有 Hot 登录”，同样需要确认和平台核对。
3. 在发现选择 QQ，可分别查看“账号推荐歌单”和“猜你喜欢歌曲”。猜你喜欢不是“每日推荐歌曲”；账号请求也不保证平台算法已个性化。
4. “我的歌单 → QQ 本人歌单”读取本人创建的目录，歌单详情每页 100 项。保留顺序、重复与无法识别的占位。支持翻页和本地歌曲收藏；**分页预览不是整单导出**，详情始终 `complete=false / integrity=page_only`。
5. “解除 QQ 关联”撤销本音乐中心的私人读取授权。更换 QQ 先解除再重新扫码。它不是 QQ 全局退出，不删除由 Hot 管理的原生凭据；原生引擎登录生命周期另行管理。Hub 退出也不等于解绑。

## 所有权与竞态

| 边界 | 当前规则 |
| --- | --- |
| fnOS 身份 | 每个私人接口、二维码图片与登录状态都重新验证飞牛 GUID；没有前台 user_id |
| 原生 Hot | 每 GUID 独立进程/端口/数据目录；登录/刷新协议只由 Hot 持有，Hub 不写凭据文件、不调用 QQMusicApi 刷新 |
| 凭据读取 | 从启动助手确定的本用户目录只读打开；逐级目录 FD / NOFOLLOW，0700 目录、0600 普通文件、同系统用户、64 KiB 上限；不能指定任意文件 |
| 不可变快照 | 每次目录调用创建独立 SDK Client 和冻结凭据值；SDK 得到 UIN/authst/登录类型等必需字段，没有 refresh/access token，也没有共享凭据池或磁盘设备缓存 |
| 绑定代次 | 开始新关联、解除、检测到 Hot 换号/运行时变化时推进；令牌轮换只增加 credential_revision，保留 AccountRef |
| 在途结果 | 平台请求返回后重新核对账号引用、代次、修订和原生凭据摘要；不一致即拒绝响应，且不缓存其中的曲目 |
| 扫码尝试 | 180 秒、本 Hub 会话专属；原生二维码 ID / 图片加密存储，业务响应不回传凭据或原生 ID；退出清除尝试 |
| 平台失效 | 返回 platform_auth_required（409），没有匿名/公共热门回退，也不使飞牛会话退出；网络失败与限流分别处理 |

固定 Hot 的二维码监听后台异步写凭据，现有 HTTP API 没有安全取消接口。关闭弹层只隐藏界面，可继续原尝试；“取消本次关联”撤销 Hub 的关联代次。即使后台迟到回写，它也不能自动授予新的 Hub 关联。不同 UIN 的回写会使已有关联失效。不要将“删除原生凭据文件”当作完整取消方案。

本门面不实现第二个刷新器，也没有宣称修好了 Hot 内部所有刷新并发。Hot 自身的条件写入、同账号并发刷新与账号任务代次仍需上游小扩展后单独验证；QQ 下载因此继续禁用。

## 来源与最小改动

| 组件 | 固定主上游 / 接入点 | 上游补丁 |
| --- | --- | --- |
| 登录与只读 Hot 存储 | HotDownloader `07e86c3d06243cf1350925c0dd3be704005abd29`；server/http.rs 的 login/qr、login/qr/id 与 core 的 qqmusic/login.rs | 无 |
| 推荐与本人目录 | QQMusicApi `27861e51432ea6b6e88dc35c4e8c8e239c0339e8`，包 0.8.2；recommend、user、songlist 的请求描述符与 Client.execute | 无 |
| Hub 适配 | modules/accounts/hot_qq.py；hub/accounts.py、account_store.py；modules/catalog/qq.py | 本工程代码，不复制签名/解析协议 |

通过上游支持的 `response_model=None` 取得原始目录项，避免严格 Song 模型把含未知项的整页拒绝；请求参数、签名、传输和协议错误仍由同一个上游构建。只转换本工程公开 DTO，不拼接别的项目解析器。

QQ SDK 为 GPL-3.0-or-later，可选依赖闭包见 requirements-qq.lock；本工程自有代码仍按 MIT 提供。后续组合发行必须保存该组件许可证、固定源码与传递依赖声明，不能把第三方 SDK 重新标成 MIT。构建附件与 FPK 尚未发布。

## 验证与下一步

受控检查分两层：本工程用真实 SQLite/保护目录/HTTP 模拟覆盖隔离与撤销；真实固定 SDK 在合成 Transport 下检查参数、账号字段、未知项、错误清洗和没有刷新调用。没有调用真实平台、没有真实扫码/会员/推荐验收。

真实用例见 [平台清单](ACCEPTANCE_PLATFORMS.md)：P-QQ-AUTH / PERSONAL / RECOMMEND。逐个记录 A/B 账号、QQ/微信登录类型、过期与 Hot 刷新、重启、解绑时在途请求，以及来源客户端同时间段的歌单/推荐结果。当前扫码适配固定 Hot 的 QQ 音乐协议，不额外宣称微信扫码已通过。

下一步继续完整歌单稳定快照、云端收藏/订阅和网易目录；QQ 下载、Hot 刷新条件写入、入库、注入执行、反馈与 FPK 仍有独立门槛。酷我 R-KW-001/002 保留原地区限制记录，待用户本地复测。
