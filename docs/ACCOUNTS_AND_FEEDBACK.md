# 账号、身份与真实反馈

本文件为设计要求。严格音桥 GUID 身份、会话与逐用户 Hot 运行时已实现并通过受控测试；真实 NAS、平台账号和客户端仍未验收，云端写入与反馈未开放。

## 严格身份

优先验证音桥的登录、请求签名与当前用户接口；只有可信上游返回有效用户 GUID 才建立实例内 Principal。官方飞牛音乐用户与 fnOS 系统用户可能有独立账号模式，必须核对映射，不按同名自动绑定。上游错误、缺 GUID、token 无效都拒绝私人操作。

身份与注入开关分开。私人读取、收藏、账号状态、下载、文件、事件流和管理员代操作全部使用同一授权门面。注销/撤销必须使后续请求和旧会话事件失效；缓存键含用户与绑定代次。

## 每用户平台账号

| 来源 | 首轮安排 | 仍需验证 |
| --- | --- | --- |
| 网易云 | 每个飞牛用户绑定自己的账号；评估现有 MusicBox 小扩展或整组件替换 | 全局配置/XDG 隔离、订阅/scrobble 缺口、真实时长参数 |
| QQ | Hot 持有登录/刷新协议，账号门面保存归属；QQMusicApi 读取不可变快照做推荐/收藏 | Hot 全局凭据改造、字段转换、QQ/微信登录类型、并发刷新、无匿名回退 |
| 酷我 | 公共歌单和 Hot 下载优先；本地收藏可独立提供 | TuneWeave 私人读写有真实实现，但真实账号验收未完成；不作为首版必装服务 |

QQ 不能让两套 SDK 同时刷新并覆盖同一文件。逐账号串行刷新、revision 条件写入；旧响应不得覆盖新凭据。`binding_generation` 表示解绑/换号等归属变化，`credential_revision` 表示同账号令牌轮换。没有逐请求凭据参数的 SDK 使用独立账号 Client，禁止并发修改全局 credential。

用户明确操作才执行云端喜欢/取消/订阅/退订；操作结果显示真实目标平台和账号。飞牛收藏不自动映射为云端喜欢，下载也不表示用户授权平台反馈。

## 播放证据与客户端能力

自动反馈需满足：用户主动启用、可信认证会话、可靠曲目映射、账号仍属于该用户、实际有效收听区间达到对应平台要求。反馈接受只说明请求被接受，不保证平台后续推荐一定变化。

| 入口 | 已观察到的局限 | 准入方式 |
| --- | --- | --- |
| 自有 Web 播放器 | 尚未实现 | 最先可控的事件链路，验证播放/暂停/缓冲/跳播/结束 |
| 音桥 Jellyfin | 当前 start/progress 返回 204，stopped 才转 track_play | 认证后增加通用事件出口，再对照 Finamp 和箭头实测 |
| 音桥 Subsonic | 传统 scrobble 的 time 是时间戳；未实现 playbackReport | 分开验证普通能力与扩展，不能宣称已有完整时长 |
| 飞牛 Web/官方 App/箭头原生 | 不能从一次 track_play 推断有效时长 | 逐版本抓取已认证事件；证据不足时关闭自动时长反馈 |
| fnmusic-sync | 取流/墙钟估算，单 current Session 有并发风险 | 仅参考采集与生命周期，不直接采用其估算做外部上报 |

箭头保留为移动客户端，其公开 GitHub 仓库只有说明/图片/许可证，没有播放器源码；不能把“支持飞牛/Jellyfin/Subsonic”当成发送完整反馈事件的证据。Finamp 是可审阅对照客户端，不要求用户替换箭头。

可信累计规则：排除暂停与缓冲；跳播的位移不计入收听；重连、重复/乱序、同曲循环、多设备并发按独立播放会话处理。以服务端时间和有界心跳间隔校验，缺结束事件不能无限计时。歌曲总时长、最后位置、读取字节数和下载耗时均不能替代实际累计。

OpenSubsonic playbackReport v1 是候选标准入口；starting 不累计缓冲时长，ignoreScrobble=true 禁止相应副作用。客户端和桥必须都实际支持后才启用，不能把扩展支持当作所有 Subsonic 客户端的默认能力。

平台反馈使用对应平台组件，通用事件出口不引用网易/QQ/酷我 SDK。不伪造推荐 token、来源页面、已听完状态或推荐效果；不确定的曲目映射与时长只留本地历史。
