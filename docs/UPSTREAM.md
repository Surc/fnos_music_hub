## 接入与更新步骤

1. 在独立工作分支核对仓库、实际默认分支、固定 SHA、LICENSE/NOTICE、语言/运行依赖和相关接口。记录版本文件、Git tag 与 commit 的对应，无法验证的字段留空。
2. 先做外围适配。需要改上游时记录最小文件/符号、原因、默认关闭的扩展接口与回归；保留独立补丁，避免复制整套前端/部署系统后长期分叉。
3. 为每个组件选一个主上游；如果现有上游不满足完整性或身份契约，明确选择修补或整体替换，不暗中混合解析器。
4. 跑本组件和跨模块契约验证；真实平台、NAS、客户端的验证结果分别记录。源码存在和 mock 通过不能推进“实机通过”。
5. 合入后才更新 `adopted_commit`、采用范围和证据提交；观察但未采用的更新只推进观察字段。保留原基线与变更历史，不重写旧工程历史或强推主分支。
6. 更新迭代、用户说明、变更记录与 skill。skill 升版同时刷新文件摘要并同步个人 Skills Git 与本仓库副本。

初始不设置自动拉取浮动 latest 的构建，不加入未经验证的 submodule 或 vendored 源码。实现阶段选择固定 tag/commit 依赖、独立上游 fork 或补丁包中最易维护的方式，并记录在清单。
