# 飞牛音乐 Hub 维护

## 先核对当前工程

1. 定位或按任务授权克隆 `https://github.com/Surc/fnos_music_hub.git`。检查 remote、分支、未提交修改；不要把旧 `fnos_music_ext` 当作本仓库。
2. 读取仓库 `AGENTS.md`、`README.md`、`SOURCE_VERSIONS.json`、`docs/ITERATION.md` 和 `docs/VALIDATION.md`；先读 `docs/RUNNING.md`、`docs/HTTP_API.md` 与功能/平台两份 `docs/ACCEPTANCE_*.md`。前台任务再读 `docs/UI_REVIEW.md`，QQ 模块先读 `docs/QQ_ACCOUNTS.md`，网易模块先读 `docs/NETEASE.md`；其余按模块读取设计、契约、账号反馈、更新和迁移文档。
3. 以当前代码和验证记录判断完成度。0.1.0a1 已有开发服务和前台；原生预览打包/实际产物/实机状态另读 `packaging/fpk/README.md`、`docs/VALIDATION.md`，不要沿用初始化时无 FPK 的状态。按当前迭代区分模拟、普通 Linux、真实平台/NAS验收。`docs/design-goals-v1.6-20261021.txt` 含后续修订的历史研究；当前规范优先。
4. 核对来源的完整 SHA、实际分支、版本文件、Git tag、观察时间、采用状态和许可证。`observed_commit` 不等于 `adopted_commit`，原工程双来源的采用基线不等于新 Hub 已采用。

## 保持模块可替换

- 三个业务模块保持独立：歌单推荐、歌曲下载、飞牛注入。身份、账号、任务归属、资产、反馈按包拆分；只在语言或故障隔离需要时增加进程，不把每个类做成服务。
- QQ/酷我下载优先验证 HotDownloader；保留其搜索、队列和下载核心，不另建第二套实际调度器。歌单推荐经 CatalogProvider 提供元数据，取流失败不得使歌曲从搜索或歌单中消失。
- FnIdentity/FnLibrary 优先验证音桥同一主上游；注入与 Socket 生命周期参考旧 ext。关闭注入后独立前台的认证、歌单和下载管理仍须可用。每个 Socket 只允许一个接管者。
- 每个协议组件指定一个主上游。版本固定，通过适配器、配置或小型可选接口扩展；记录补丁、范围、验证和回退。不要把不同上游的解析器暗中拼到同一个组件。
- `TrackRef` 使用平台、ID 类型和字符串 ID；保留实际下载来源/格式。跨平台匹配须核对歌名、歌手、版本与时长，不能把试听、翻唱或转码标为原版高音质。
- 歌单下载交付完整、有序、不可变的清单；保留重复出现和未知条目，验证分页/总数/哈希。接单持久化、幂等和恢复必须成立；下载完成、文件验证、入库状态分开记录。

## 用户身份、凭据与反馈

- 所有私有读取、写入、事件和文件访问由服务端验证的 fnOS 实例与用户 GUID 授权。无效会话、缺 GUID 或上游异常应拒绝，不能降级 shared/admin、信任前台 user_id 或继承上个用户。
- 本地收藏、云端喜欢/订阅、导入快照分别建模。逐用户绑定平台账号；Cookie/令牌只保存在服务端受保护存储。日志、Git、文档和浏览器响应不包含凭据。
- QQ 首轮登录/刷新协议由 Hot 持有，账号门面管理归属；QQMusicApi 只获得不可变账号快照，不竞争刷新。逐账号串行刷新和条件写入；`binding_generation` 与 `credential_revision` 分开。现有 Hot server 全局凭据须先解决隔离，不能并发切换共享 Cookie。
- 网易协议先评估现有 MusicBox 小扩展或整组件替换；不要默认引入第二套常驻 SDK。酷我私人账号、TuneWeave、酷狗等为独立验证项，不自动扩张一期范围。
- 仅用户启用反馈且有可信实际播放证据才上报；下载、预取、文件字节数、歌曲总时长或最后位置都不是有效收听时长。排除暂停、缓冲和跳播；处理重连、乱序、循环、并发设备和账号解绑。
- 音桥现有 Jellyfin start/progress 不保留完整状态，普通 Subsonic scrobble 的 time 是时间戳；不能声称已经支持完整反馈。fnmusic-sync 的取流/墙钟估算只可作参考；箭头各连接模式必须实机核对。没有可靠证据时保留本地历史和明确云端操作，关闭自动时长上报。
- 上游接受反馈不等于推荐算法已学习。远端写入超时状态为未知时先回读，避免盲目重发非幂等操作。

## 当前开发版的验证边界

- PC/移动端均需横/竖屏；手机横屏使用紧凑侧栏、低高度确认页，竖屏使用底部四入口。管理员设置从“我的”可达。当前前台已接搜索、收藏、任务/文件、批量选曲和下载确认；推荐/私人绑定/入库/注入仍按实际后端能力标为未开放，禁止放入原型示例数据。
- 保持旋转仅调整布局与可见视口，不重建表单、不重新认证或提交。下载结果不明时冻结原音质/目标，以原清单、请求体和幂等键核对；退出清除路径、弹层与私人筛选。旧用户的迟到响应不能写入新会话或将其登出。
- 前台改动运行 jsdom 与 `npm run test:browser`。后者用真实 Chromium、合成同源 API 做尺寸/旋转/溢出及页面流程检查，属于开发机/CI 依赖，不进入 NAS。真实手机键盘/安全区、NAS 身份和真实平台仍按验收清单单独记录。

- 2026-10-21 的真实 Hot HTTP 搜索能找到 DAYBREAK'S BELL（RID 142276943）和晴天（RID 228908）；本环境两次下载都被酷我地区限制 407 拒绝。不能沿用“Hot 在其他环境成功”来认定本次下载通过。
- 保留这两项历史结果，业务码不当作 HTTP 状态。R-KW-001/002 由用户稍后本地复测，不改变网络环境代测，不冻结其他模块开发。
- 当前下载仅开放酷我，QQ/酷我公共搜索仍独立；可选 QQMusicApi 库已接扫码后显式关联、账号推荐/猜你喜欢和本人创建歌单分页，真实账号/NAS 尚未验收。猜你喜欢不是每日推荐，personalization=unverified；分页预览 complete=false，不当作完整歌单。网易、云端写入、入库、注入与真实播放反馈仍有独立准入。
- `scripts/run_hot_user.py` 初始化 Hub 专属原生引擎；`scripts/live_hot_smoke.py` 是显式真测工具，音频和原始日志放在仓库外，不用作生产认证入口。
- 自有代码 MIT；Hot/音桥通过 HTTP 对接，可选 QQMusicApi 固定库为 GPL-3.0-or-later，组合发行保留其许可证/固定源码。没有复制或修改其运行源码。真实构建 Hot 时要获取固定子模块并保留其 LICENSE/NOTICE。

## QQ 账号与只读目录接续

- 保持 `qq_accounts_enabled=false` 的基础模式与独立 Hot 数据目录；QQ 可选依赖见 requirements-qq.lock，不增加常驻 SDK 服务。缺依赖时明确拒绝启用。schema 1/2→3 升级前备份数据库与密钥，不能让旧程序直接降级读取。
- QQ 扫码通过本人 Hot；confirmed 只是候选，核对账号后显式 bind 才授予读取。尝试 180 秒且属于当前 Hub 会话，退出清除；二维码 ID/图片加密，秘密不进业务响应。
- 固定 Hot 无原生二维码取消，后台仍可能回写。取消/解绑撤销 Hub 代次，不依赖删文件或原生 logout 防迟到写入；换 UIN 立即使关联失效，不能自动绑定迟到账号。Hot 内部刷新条件写入仍待验证，QQ 下载保持关闭。
- 只读打开本用户 0700/0600 原生凭据，逐级 FD/NOFOLLOW/大小和所有者校验；每次 SDK Client 使用冻结账号值，不提供 refresh/access token，不使用共享凭据池。平台读取后重验 AccountRef/代次/修订/摘要，再缓存或返回，正常同号刷新不推进绑定代次。
- 用 QQMusicApi 上游请求描述符/sign/错误处理，response_model=None 保留未知项；推荐沿来源 next_cursor，不能按固定步长猜下一页。平台 auth_required 用 409 区分飞牛 401，禁止匿名回退。SDK 合成 Transport 测试不证明真实签名/设备/推荐效果；浏览器合成 QR 也不证明真实扫码。

## QQ 完整快照接续（2026-10-23）

- 先读 `docs/QQ_SNAPSHOTS.md`。保留实时分页 `complete=false/page_only`；完整快照单独走按用户持久化的 capture 句柄与原 manifests 表，不新增下载调度器。
- `complete=true/integrity=double_read_verified` 必须两轮全部分页的总数、页长、结束标记、目录信息与原始有序条目哈希一致，账号/代次/修订不变且会话仍有效。无已验证上游版本，`source.version=null/atomic=false`；不宣称可检测 ABA/稳定旧缓存或具有单时刻原子性。
- 最多 1000 项/512 KiB；保序、重复和未知位置，未知只保存白名单原始标量与原条目哈希，不存任意上游报文。中断/超时/漂移不发布部分清单；恢复句柄后显式从第一页重新两轮验证，不能拼接旧页。限流冷却按用户持久化，不能新建请求绕过。
- 同号刷新在途失败、下次重试用新 revision 从头；解绑/重绑不能继续旧 capture。已导入不可变快照属于飞牛 owner，解绑不隐式删除。每次快照/明细/恢复检查 owner；SDK 与 Hot 上游均零补丁。
- 验证包含大歌单、等数换曲/重排、unknown 变化、真实异步超时/取消、双用户/会话撤销、schema 2→3 与重启恢复、真实固定 SDK 的两轮 offset 请求，以及前台分页/确认/旋转/丢响应回读。真实 QQ/NAS 另走 R-QQ-005/006；快照成功不解禁 QQ 下载。

## 快照故障恢复与本地历史

- 初始状态写入及取消清理失败也必须释放 owner 运行占用；验证 SQLite 故障后不重启仍可重试，以及完成/删除事务回滚。不要只测平台错误。
- 本地快照历史独立于 QQ 实时目录和关联状态，仅依赖飞牛 owner 授权；历史使用游标分页，前台不能用旧历史覆盖已完成结果，临时平台故障不清空本地入口。
- 删除由用户在本地历史中明确确认；运行中的 capture 拒绝删除。事务删除对应远端清单内容并保留 deleted 请求记录、幂等键及 retry_at；同键不能重新抓取，不能通过删除绕过冷却。既有下载清单/任务不清理。SQLite 空闲页可复用，缩小文件须停机备份后另行维护。
- 前台回归加入 1000 项原序/重复/未知、解绑后本地访问、历史分页、确认删除与迟到响应；真实 QQ/NAS 和 1000 项以上扩容仍按独立范围验收。

## Astra 审核修复的接续约束

- 先读 `docs/ASTRA_REVIEW_FIXES.md`。保留每个原生控制动作之前的持久化意图与逐项回读；部分失败和进程重启后继续核对已知 engine_id，不盲目重发。按原生状态决定能否操作，多个 Hub 任务/重复条目共用一个 Hot job 时也要同步状态；Hot completed 但本地校验失败的重试只重新校验文件。
- 保持每任务串行和有界并发：最多 4 个核对流程、1 个完整音频解码；不同任务的控制不等待全局解码锁。轮询只查询活动索引，不能每轮反序列化全部历史。
- 会话撤销后，外部等待返回及提交/缓存/控制等边界重验本地会话；已经接收并持久化的下载仍归 owner 继续执行。退出清理本会话尚未绑定的登录尝试，不撤销已完成关联或他会话的新尝试，迟到扫码不能重新写回。
- 下载文件逐级使用目录 FD 与 NOFOLLOW 打开，校验和读取使用同一 FD；覆盖父目录替换、符号链接和非普通文件。前台分页成功后才更新页码/游标，慢轮询只保留同上下文的一个在途请求，退出/切页仍使迟到响应失效。
- 来源清单的采用 SHA 必须有已合并的适配器/依赖证据，并写明 HTTP 接入或可选 SDK，不能冒称复制上游源码或完成实机验收。检查数据库常量、完整快照能力与清单一致，保留旧工程双来源和历史地区限制结果。
